# 架构

```text
Windows QQ → SnowLuma 正向 WebSocket
                  ↓
WSL MaiBot 1.3.15 + 官方统一 QQ 连接器 1.1.8
  ├─ 人设、开口判断、对话上下文、表达与记忆
  └─ doraymon_meal SDK 插件
       └─ doraymon.meal
            ├─ 本地候选 SQLite → 校内外/类别筛选 → 随机选店与换店
            ├─ 高德 Web 服务 → 附近门店
            ├─ 可选 SQLite 资料库 / 商家菜单 JSON / 小红书 MCP / 点评 MCP
            │    └─ 带出处、时间及版本的资料与结构化菜品
            └─ MealReport → Planner 事实 / HTML / Markdown / JSON

doraymon.ops    仓库配置 → 独立实例目录
doraymon.replay 假 NapCat → 候选 MaiBot → 合成回放报告
```

Windows 桌面使用 WebView2 原生窗口和托盘。`doraymon.desktop` 仅公开固定操作，通过现有监督入口管理机器人；管理凭据由当前 Windows 用户的 DPAPI 保护，页面 JavaScript 不接触凭据。`doraymon_admin` SDK 插件的管理接口只监听 WSL 本机回环，QQ 命令使用宿主原始消息确认管理员身份，与桌面共用 `AdminService`。执行记录持久化请求摘要与结果，不保存消息正文；结果未确认时不自动重发。

`doraymon.catalog` 保存具体分店、城市、片区、品类和来源，独立采集服务从公开目录补充资料。桌面优先读取已连接管理接口，QQ 离线时直接读取同一份 WSL JSON；WSL 不可用时才显示带提示的 Windows 快照。采集控制通过固定的 `doraymon.catalog_control` 命令操作同一服务，不依赖 QQ 登录。公开目录的公布总数、可读条目与覆盖缺项分别保留，提前结束不能记为全量完成。

热门名单另存 `ranking-index.json`，与已经入库的门店独立核对。`catalog_rankings_sources` 读取公开推荐及高德年度榜单，保留原文日期、页面更新、榜单年度、实际读取日期、原始名次与名单顺序；后两者不互相替代。原始页面按 URL 与内容摘要留存。未匹配条目计入待核对缺口，同一分店跨名单合并后只计一次；完整店名与地址一致可自动对应，其余由带依据与链接的明确决定导入或暂缓。重取页面保留仍对应相同店名、地址的已核对结果，失败保留上次快照。

高德门店页的地址、名称和暂停营业等提示与原名单字段分别保存。来源提示停业的门店仍留在资料库，但不参与本地随机推荐。采集目录和榜单共用锁及暂停状态；公开目录读完、名单匹配、品牌分店覆盖和菜单核实分别统计。

综合 100 与全部来源候选分开导出。候选超过 100 时仍保留全部未匹配项，避免列表上限隐藏分店缺口。饮品品牌核对记录已录数量、片区及未知的全市总量；采集目录读完不自动证明品牌覆盖完成。中英文区域标签统一后仍保留来源标签；携程有明确中文地址时优先采用，并保留原显示地址及餐厅身份关联。空的外部地图标识不清除已有核对结果。

## 维护边界

| 路径 | 职责 |
|---|---|
| src/doraymon/meal | 不依赖宿主的检索条件、高德查询、资料适配、统一快照和导出 |
| plugins/doraymon_meal | SDK 参数转换、成员识别、有界任务与状态、阶段提示、地图和文件发送 |
| src/doraymon/ops | TOML 覆盖、插件复制、锁定连接器安装与 NapCat 接入文件解析 |
| deploy/maibot | 无密钥的公共配置覆盖项 |
| deploy/local.example | 本机账号、名单和隔离回放实例的示例 |
| src/doraymon/replay、evals/scenarios | OneBot 替身、时间轴播放、回复统计及合成场景 |

聊天引擎、QQ 协议、重连、学习和记忆由上游维护。候选版本没有继承 slim 的聊天队列、停止和静默规则；这些使用体验需要通过真实回放及 QQ 试运行核实。

## 配置与实例

MaiBot 与 SDK 由 uv.lock 锁定。官方连接器由安装命令固定下载 v1.1.8，其配置结构版本为 2.7.1；不将上游源码复制进本仓库。

实例默认位于 ~/.local/share/doraymon/maibot，保存 config、data、logs 和 plugins。本机覆盖项默认位于 ~/.config/doraymon。仓库、凭据和运行数据分开保存。

prepare 以 MaiBot 生成的配置为底稿合并覆盖项，保留注释，拒绝未知键和明显类型不符，逐文件原子写入。数组整体替换。check 只比较并报告差异，密钥及嵌套列表中的密钥均遮盖。多文件更新不承诺整体事务，应用配置时应停止实例并先备份。

run 只同步插件及显式提供的 NapCat 地址，不重新覆盖 WebUI 修改的人设、模型和访问规则。首次配置或重新应用仓库策略用 prepare。

插件代码复制到实例，保留实例自身 config.toml；缺失源码或既有插件符号链接会停止同步。命令以仓库可编辑安装为运行方式，wheel 只包含 Python 包，不能单独替代 deploy 和 plugins 目录。

## 用餐事实与状态

- campus_food 和 nearby_food 的 msg_id 来自当前聊天记录；插件通过 message.get_by_id 将查询限制在当前聊天流，并从宿主消息获取成员 ID。模型填写的昵称不参与状态键。
- campus_food 以只读连接访问 candidate_database_path，要求 application_id=0x44534352，支持旧校区库 schema_version=2 与城市库 schema_version=3。城市库按已支持的地点别名选择南昌／荆州及校区、瑶湖、红谷滩或前湖范围；门店名、类别、地址与归属依据来自库。校内/校外筛选不包含空归属；类别按明确分组词匹配，未匹配不自动放宽。SQL 随机抽取 1～3 家，状态继承筛选并保存最近 256 个选择 ID，同一轮排除已选记录，换条件或 reset 开始新一轮。状态同样限制为 512 项/默认 30 分钟，换店与停止沿用成员锁和任务清理；本地选店清除该成员旧的地图快照，避免后续发送上一家地图。
- 用餐人设与工具说明要求基于本次工具结果自然给出选择，随机抽取不作为排名、口味或环境判断。候选来源是用户截图与公开门店资料，归属只表示资料标注，当前营业尚需核对；本地选店不调用模型生成事实或发起地图请求。
- 状态以聊天流和成员 ID 为键，最多 512 项，默认 30 分钟过期；同一成员串行更新，不同成员可并发，插件最多保留 32 个在途任务。不同地点重新开始选择，同地点保留预算、口味场景要求和排除店铺；空字符串可清除要求。
- 高德公共结果按起点和半径缓存，最多 128 项、默认 5 分钟；缓存不保存个人条件。
- 高德 v3 查询使用 extensions=all，读取实际存在的分类、特色标签、评分与人均参考。店名、地址、直线距离只来自高德；评分与人均不证明菜品、现价或用户体验。当前仍按高德距离顺序取请求数量，未实现全区域菜品筛选与自动口味排序。
- MealReport 保存候选、资料出处、获取时间、可用的发布时间、分店对应及来源覆盖状态。商家 JSON 按高德地点 ID 对应；点评要求名称和具体地址一致才标为对应分店；小红书始终作为分店待核对的体验线索。获取时间不替代原文更新时间，不将旧菜单写成现价。
- MCP 使用锁定的 mcp 1.30.0 SDK 和 Streamable HTTP，仅调用 search_feeds、get_feed_detail、dianping_search、dianping_shop。各远程来源并行，单来源串行保护与等待上限包含排队；失败保留其他来源和已获得的候选资料。未配置时不调用，不读取或共享其他成员的检索结果。
- SQLite 使用标准库 sqlite3，空 meal_database_path 禁用。branches 保存高德地点 ID 与门店元数据，去掉与本次起点相关的距离；records 保存带范围、来源、获取时间和内容摘要的不可变观察版本，结构化菜品保存在经过 Pydantic 校验的 JSON 内。菜品可记录名称、单品/套餐、规格、做法、口味、分量、价格及堂食/外卖，缺失值保持未知，不作自然语言自动抽取。
- 资料库先查当前高德候选的已存记录，默认获取超过 24 小时就重查已配置来源；90 天以前的原文和没有原文日期的体验记录也标记待复核。缓存读取不改原始获取时间，重查失败时保留带标记的旧记录。时间阈值只决定重查与展示，不能证明当前供应或现价。查询每家最多载入 32 条最新资料文档，报告最多 8 条，优先未超期记录，再按菜单及获取时间排序；历史查看最多 100 条，旧版本仍留在库中。
- 商家 JSON 是运营者选择的共享导入资料；自动取得的外部结果使用聊天流/成员及用餐要求派生的哈希范围保存。同一成员换要求会补查，不把查询原文、原始成员标识、个人起点或消息 ID 写入库。无可核实成员范围时不自动持久化远程结果。CLI 导入报告必须明确选择共享资料或本机私有范围，私有范围不会出现在公开查询和导出中。
- 单次资料批次与门店更新使用同一事务，按真实获取时间选最新版本，乱序旧资料不会盖掉新记录；同一观察记录重复导入幂等。连接在执行线程内创建并关闭，锁等待有上限，库错误以来源状态返回，不阻断地图结果。数据库有 application_id 和 user_version，未知或未来格式拒绝读写，不重置既有数据。数据库保存在仓库外，文件权限为 600；资料文件与相关日志文件名已忽略入库。
- 阶段提示默认延迟 2 秒、间隔至少 8 秒、最多 3 条，快速完成不发。完成和取消均等待提示任务清理；新查替换同成员旧任务，cancel 停止并清除其状态。热更新等待在途任务结束后重建服务，卸载取消任务并关闭连接。宿主是否及时触发停止工具仍需真实 QQ 验证。
- 地图链接由工具直接发送；只有 send.text 返回 sent=true 和有效最终消息 ID 才报告成功。未确认时不自动重发。普通文字的最终表达和投递归 MaiBot。
- meal_export 直接渲染该成员尚未过期的快照，通过 send.custom 的 file 组件发送，文件不超过 1 MiB；只在有最终消息 ID 时确认送达。文件内容内存生成，不积累实例导出文件。HTML 无脚本、外部资源或内嵌地图 Key，仅保留外链；导出不含聊天流、成员、消息 ID、提问原文和个人起点。外部资料按引用呈现，URL 的已知凭据参数移除，小红书访问 token 不落入快照。

## 回放与验证范围

FakeNapCat 提供连接器所需的基础 OneBot v11 动作、鉴权、心跳、消息引用及发送记录。未知动作返回失败并记入报告；断线不静默丢弃场景消息。

场景按相邻步骤之间的时间窗检查应答与静默。分数使用未舍入的时间，报告中的时间仅为显示取两位小数。不同群场景采用独立合成群号；实际对比前使用干净的独立实例，避免旧聊天、学习和记忆影响结果。

报告包含漏答、多答、气泡总数、长度中位数/P90、首答延迟 P50/P95 和未知动作。存在漏答、多答或未知动作时退出码为 1，配置、断线、引用前提或就绪失败时为 2。这里尚不采集调用次数、token、费用，也不自动判断事实与语气；这些由 MaiBot WebUI 和人工评阅补齐。

当前 10 个场景覆盖私聊追问、引用机器人、让开其他成员、成员停止、用餐追问、称呼与语气、连续补充，以及瑶湖校区信息追问和检索停止后改查校外。后两组只完成离线准备，其菜品、校区、时效和取消判定须人工核对，自动 reply/any 评分不能证明事实正确或即时停止成功。尚未移植旧版全部 16 个开发场景和 8 个保留场景；只有回放台自身经过替身测试，尚未将真实 MaiBot 接入回放台。

接口核对依据：[MaiBot 安装与实例目录](https://docs.mai-mai.org/manual/deployment/uv-tool)、[官方 QQ 连接器](https://docs.mai-mai.org/manual/adapters/qq-local-client)、[连接器 v1.1.8 配置常量](https://github.com/Mai-with-u/MaiBot-SnowLuma-Adapter/blob/v1.1.8/constants.py)、[SDK 2.16.0 指南](https://github.com/Mai-with-u/maibot-plugin-sdk/blob/v2.16.0/docs/guide.md)。版本相关行为同时以当前锁定安装源码及临时实例测试核对。

SQLite 接口依据：[Python 3.13.15 sqlite3 文档源码](https://github.com/python/cpython/blob/v3.13.15/Doc/library/sqlite3.rst)、[SQLite PRAGMA](https://www.sqlite.org/pragma.html)。本机验证为 Python 3.13.15、SQLite 3.53.1；事务提交/回滚与连接关闭分开处理，跨线程不复用连接。
