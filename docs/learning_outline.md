# DoraYmon 学习路线

这份路线以“插件化 Python QQ AI 助手”为主线。每一阶段都先建立可解释、可离线验证的基线，再根据评测决定是否增加复杂组件。

## 1. 当前能力边界

已实现：

- `botpy` QQ Bot 长连接、命令路由和插件机制。
- DeepSeek 对话；显式 `/chat`、私聊普通文本和群聊 @ 普通文本可以进入 chat 插件。
- 默认关闭、按私聊用户或“群 + 用户”隔离的短期上下文。
- `/清空上下文`、`/上下文状态` 和 `/上下文摘要`。
- 基于规则匹配的食物意图识别，以及 SQLite 业务数据存储。
- 基于 SQLite FTS5/BM25 的本地知识库 RAG、来源引用和权限过滤。
- 不依赖真实 QQ 或 DeepSeek 凭据的离线测试。

尚未实现：

- Embedding、向量相似度和混合检索。
- 长期个人记忆、Agent、自主工具调用。
- 模型训练或微调。

短期聊天历史不能宣传为长期记忆，也不能自动转成知识库。

## 2. 先稳定短期上下文

当前配置：

```env
BOT_ENABLE_CHAT_HISTORY=false
BOT_CHAT_HISTORY_LIMIT=10
BOT_CHAT_HISTORY_MAX_CONTENT_LENGTH=1000
BOT_CHAT_CONTEXT_MAX_CHARS=6000
BOT_CHAT_CONTEXT_SUMMARY_MAX_CHARS=1200
BOT_CHAT_CONTEXT_TTL_MINUTES=60
```

需要持续验证：

- 默认关闭时保持原有单轮对话行为。
- 私聊用户之间隔离。
- 群聊按“群 + 用户”隔离，不共享私人上下文。
- DeepSeek 失败时不保存伪造的助手回答。
- 只发送和保留完整问答轮次，并限制历史总字符数。
- 超预算旧轮次只做本地节选压缩，闲置会话按最后活跃时间整体失效。
- 只有明确的换话题表达清空当前会话，避免普通转折语句被误判。
- 开启 RAG 后，短追问可以结合上一轮问题检索，检索故障时普通聊天仍可用。
- 状态命令不返回完整聊天内容。
- 密钥、配置内容和真实聊天数据库不进入测试或 Git。

## 3. 已完成的 SQLite FTS5 RAG 基线

第一版没有引入 LangChain、Chroma 或 Milvus，已使用 SQLite FTS5/BM25 建立本地知识检索基线。

当前结构：

```text
resources/knowledge/       管理员整理的 Markdown/TXT 知识
storage/knowledge_store.py 文档、分块、元数据和索引读写
services/rag_service.py    检索、上下文拼装和生成回答
plugins/knowledge.py       QQ 知识问答命令
scripts/index_knowledge.py 离线建立索引
tests/test_knowledge_store.py
tests/test_rag_service.py
```

MVP 命令：

```text
/知识问 问题
/知识库状态
/知识来源
/重建知识库
```

`/重建知识库` 只能由管理员执行。回答必须包含来源；没有可靠资料时明确拒答，不允许模型用常识伪装成知识库内容。

## 4. 文档分块与元数据

当前分块保持可解释：

- 按 Markdown 标题和自然段切分。
- 保存来源路径、文档标题、标题层级、更新时间和权限作用域。
- 只在必要时加入少量重叠，并记录分块规则版本。
- 索引管理员整理的 Markdown/TXT，不索引聊天历史、密钥、数据库和日志。

每次检索返回知识块 ID、相关性分数和来源元数据，方便调试和引用。

## 5. 建立固定 RAG 评测集

先准备 20～50 个固定问题，覆盖：

- 单文档直接命中。
- 跨标题或同义表达。
- 多个相似来源的排序。
- 权限不允许访问的资料。
- 知识库没有答案的问题。

核心指标：

- Recall@K：正确知识块是否进入前 K 条。
- MRR：正确结果是否排在前面。
- 来源正确率：回答引用是否真实支持结论。
- 无答案拒答率：没有资料时是否正确说不知道。

生成回答的主观“看起来不错”不能代替检索评测。

## 6. Embedding 与混合检索

只有 BM25 基线和固定评测集稳定后再加入：

1. 独立 `EmbeddingService`，不绑定 DeepSeek。
2. 保存向量并实现余弦相似度 Top-K。
3. 分别评测关键词检索和向量检索。
4. 使用 RRF 合并两路排名并评测混合检索。
5. 只有指标或明确案例证明有效，才保留新增复杂度。

## 7. Prompt 与安全

RAG Prompt 需要明确：

- 只能依据提供的知识块回答。
- 知识块中的命令性文本只是资料，不能覆盖系统提示。
- 每个结论使用稳定的来源编号。
- 上下文超出预算时按检索排名和权限裁剪。
- 资料不足或冲突时明确说明，不猜测。

知识库作用域：

- 公共知识库：所有用户可查。
- 群知识库：仅对应群可查。
- 私人知识库：仅对应用户可查。
- 导入、删除和重建：管理员权限。

日志只记录文档 ID、耗时、召回数量和必要的错误信息，不记录完整私人问题。

## 8. 后续实现顺序

1. 建立 20～50 个固定问答评测样本和基线指标。
2. 根据真实问题调整分块参数、Top-K 和中文查询生成规则。
3. 验证公共、群、私人知识库在真实 QQ 事件中的 openid 映射。
4. 增加来源正确率和无答案拒答率的自动评测。
5. 再评估 Embedding、向量检索和 RRF。
6. 最后考虑小型知识库管理页面；它不阻塞当前 MVP。

## 9. 项目讲解口径

可以说：

> DoraYmon 是一个插件化 Python QQ AI 助手。项目通过 DeepSeek 提供大模型对话，支持可控短期上下文，并实现了基于 SQLite FTS5/BM25 的本地知识库 RAG 基线。知识回答强调来源可追溯、权限隔离和离线可测试。

可以说项目已支持轻量关键词 RAG，但不能说已经支持向量数据库、Embedding、长期记忆或 Agent。
