# 回复风格与模型参数

DoraYmon 的回复由公开人格、运行上下文、短期历史和可选资料共同决定。模型输出经过统一后处理，再交给 QQ 发送层；普通文本不依赖 Markdown 渲染。

## 普通聊天

- 先直接回答，再补充必要的解释或一个确认问题。
- 不把缺少的事实说成已经执行，不泄露内部配置、密钥或用户标识。
- 历史只使用当前私聊用户或当前“群 + 用户”的完整问答轮次。
- 开启 RAG 时，只把相关度足够高的前 1～2 条资料放进普通聊天提示词；只有模型引用资料编号时才追加简短来源。

默认模型参数：

| 场景 | 温度 | `max_tokens` |
| --- | ---: | ---: |
| 无可选资料的普通聊天 | 配置值 + 0.1，上限 2.0 | 8192 |
| 含可选资料的普通聊天 | 配置值与 0.4 取较小值 | 4096 |
| 严格 `/知识问` | 配置值与 0.4 取较小值 | 4096 |

模型名称仍由 `DEEPSEEK_MODEL` 控制，不会自动切换到更强模型。模型失败时返回简短错误提示，失败回复不写入聊天历史。

## 长回复与 QQ 发送

单段最多 1800 个字符，默认最多发送 3 段，总长度默认不超过 4000 个字符；多段发送使用递增的 `msg_seq`。超过总长度才截断，并明确提示用户。具体上限可通过 `BOT_REPLY_MAX_SEGMENTS` 和 `BOT_REPLY_MAX_TOTAL_CHARS` 调整。

## 严格知识问答

`/知识问` 只能依据检索资料回答。无资料或资料不足时明确拒答，不用普通聊天常识补全；回答引用实际来源编号，接口错误不保存为知识答案。

长期个人记忆尚未实现。短期聊天历史和摘要不会自动转为长期记忆或知识库。

模型的生成上限包含推理 token，不等于用户可见字数。达到生成上限的非空回答会标注未完成；空正文按模型错误处理，不保存为成功对话。不自动续写或重试。

聊天与知识回答在保存历史前按发送上限裁切，CLI 和 QQ 使用同一份正文。分段保留内部空白和代码缩进；发送失败时历史仍可能包含未送达内容，尚未实现送达确认。
