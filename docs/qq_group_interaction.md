# QQ 群聊交互

QQ 账号入口启用后默认接收普通私聊，普通群消息按内容选择性接话。此处描述源码行为与合成验收，不代表运行实例已经加载或通过真实 QQ 验收。官方 QQ Bot 和飞书的入口范围各自保留。

## 可以直接说什么

| 合成输入 | 预期行为 |
|---|---|
| 非好友名单中的用户私聊“你好” | 回退到普通聊天 |
| 群里“谁知道 Python 列表怎么去重？”→“要保留顺序呢” | 首句选择性接话，追问沿用该成员个人历史 |
| “吃什么”→“换一个”→“15元以内”→“地图” | 连续调用用餐流程，保留未改条件，地图对应当前选择 |
| 甲“预算15元”、乙“预算50元” | 记录发言人，两个成员的用餐状态分别保留预算 |
| 引用机器人“这句是什么意思” | 补引用作者和正文，经真实路由处理；不要求额外 @ |
| @ 其他成员或引用其他成员的发言 | 未同时叫机器人时让开 |
| “今天好热啊”“哈哈哈”“谢谢” | 可以不答，不为维持活跃追问 |
| 甲“没问你”或“不用回复了”→乙 @ 机器人 | 结束甲分支并取消旧任务；乙仍能提问 |
| 停聊后再次 @、引用或叫机器人名字 | 可重新发起该成员对话 |

发言判断先用本地规则，不为每条普通消息调用模型。明确求助、知识问题和用餐请求是首版选择性参与的触发信号；反问、含蓄表达和复杂指代仍可能误判。合成检查只验证路径、提示词资料和状态，不能证明模型会自然回应或一定正确理解每个发言人。

## 访问与节奏

| 配置 | 默认值与作用 |
|---|---|
| `BOT_QQ_ACCOUNT_ENABLED` | `false`；仍需显式开启账号入口 |
| `BOT_QQ_ACCOUNT_ACCESS_MODE` | `chat`；普通私聊与群成员均可进入；`allowlist` 恢复封闭名单模式 |
| `BOT_QQ_ACCOUNT_GROUPS` | 空时处理账号所在群；chat 模式下非空时仍限定群范围 |
| `BOT_QQ_ACCOUNT_FRIENDS` | 只在 allowlist 模式限制用户；两份名单皆空时 allowlist 拒绝启动 |
| `BOT_QQ_ACCOUNT_GROUP_PARTICIPATION_ENABLED` | `true`；关闭后保留 @、引用、名字、命令和连续追问 |
| `BOT_QQ_ACCOUNT_BOT_NAMES` | `DoraYmon,哆啦A梦,哆啦,小哆`；识别句首称呼 |
| `BOT_QQ_ACCOUNT_GROUP_PARTICIPATION_COOLDOWN_SECONDS` | `30`；普通参与每群冷却秒数 |
| `BOT_QQ_ACCOUNT_GROUP_PARTICIPATION_MAX_REPLIES` | `2`；普通参与每群每分钟成功送达的回复轮数 |
| `BOT_QQ_ACCOUNT_GROUP_COOLDOWN_SECONDS` | `0`；直接请求与连续追问冷却，已有非零配置仍生效 |
| `BOT_QQ_ACCOUNT_GROUP_MAX_REPLIES` | `8`；直接请求每群窗口内成功送达的消息段数 |
| `BOT_QQ_ACCOUNT_GROUP_RATE_WINDOW_SECONDS` | `60`；直接请求限频窗口秒数 |

两条限频通道分别计数；普通参与冷却不阻挡直接提问和连续追问。拒绝或未知的发送结果不激活连续对话、不计入发言额度，也不写入历史。同群不同成员可同时生成，最终发送前在各通道内串行检查额度。静默在生成前和每段发送前生效。

连续对话从成功送达开始，闲置 120 秒失效；“谢谢”等简单收尾不触发回复。局部停聊暂时抑制该成员的自动参与，直接请求可重开；其他成员不受影响。停聊取消尚未完成的生成和排队输入，不撤回已经送达的消息，也不删除已有个人问答历史。`/清空上下文` 另清个人历史、摘要、用餐状态与其公共分支。

群公共窗口只在内存保存，至多 128 个群，每群 24 条、约 6000 字符、5 分钟；每条正文和引用节选最多 600 字符，每群活跃/停聊分支分别最多 128 人。窗口按平台、机器人账号、群隔离，进程结束即消失。发言人、时间、提及、引用及回复对象作为不可信资料交给模型；不注入私聊历史，不把别人的条件写进当前成员用餐状态。外部引用必须核对群号才补正文；缺失范围时只解析作者，跨群/私聊正文不进入当前群请求。个人历史仍只保存本人请求与确认送达的回答。

## 离线复现

```bash
.venv/bin/python -m unittest tests.test_group_dialogue
.venv/bin/python -m scripts.preflight_offline
```

[合成语料](../tests/fixtures/group_dialogues.json) 固定为 16 组开发样例和 8 组保留样例，均只使用虚构身份、场所和内容。测试从 `AccountRunner` 经过实际适配、会话、路由和业务插件，用假模型、假地图/传输与临时 SQLite 验证可见回复、引用目标、连续条件和局部取消；另覆盖慢查询取消、并发限频、未送达历史和静默。

真实模型的语气、误插话比例、漏答和真实 QQ 的 @/引用/连续往返仍需分别验收。短时间输入合并、跨重启日预算、菜单来源覆盖等未在本批实现，本批不代表整个 P1b 或 G0～G3 完成。
